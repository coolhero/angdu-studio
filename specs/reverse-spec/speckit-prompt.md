## Key Migration Notes for SDD Spec Generation

When generating SDD specs for each feature, the following migrations apply:

1. **UI Components**: All Ant Design components must be replaced with shadcn/ui + Radix UI equivalents. Reference `stack-migration.md` component map.
2. **State**: All Redux Toolkit slices must be reimplemented as Zustand 5 stores. Reference `stack-migration.md` store mapping table.
3. **Styling**: All styled-components must be replaced with Tailwind CSS 4 utility classes. Use `cn()` (clsx + tailwind-merge) for conditional classes.
4. **Identity**: All references to Cherry/CherryStudio/@cherrystudio must use Angdu/AngduStudio/@angdu.
5. **Persistence**: redux-persist → Zustand persist middleware. Per-store keys with `angdu-` prefix.

## Architecture Constraints for SDD Specs

- Main process services are singletons accessed via `getInstance()`
- All renderer↔main communication via typed IPC channels (`IpcChannel` enum)
- AI provider calls go through Vercel AI SDK abstraction (never direct HTTP)
- MCP servers run as child processes of main process
- Renderer uses Dexie for messages/topics, Zustand for app state
- Main process uses Drizzle+LibSQL for knowledge base data
