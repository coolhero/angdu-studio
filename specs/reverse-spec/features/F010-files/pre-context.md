## 1. Runtime Exploration Results

**Screen**: `#/files`

**Layout**: Navbar ("Files" title) + left sidebar (file type filter: Document, Image, Text, All) + main content area (sort controls + file list)

### UI Elements
- Left sidebar: File type menu items (Document, Image, Text, All) with icons, active highlight
- Sort controls: Sort by (created_at, size, name) buttons with asc/desc arrows, batch operation checkbox with dropdown (batch delete)
- File list: File items with name (clickable to open), size, created date, actions (rename, delete with confirm, checkbox for batch)
- Batch operations: Select all checkbox, batch delete with confirmation popup
- Empty state: Empty component when no files match filter

### User Flows
| Flow | Steps | Observations |
|------|-------|--------------|
| Browse files | Select file type tab -> View filtered list | Dexie live query updates reactively |
| Sort files | Click sort field (date/size/name) -> Toggle asc/desc | Re-sorts displayed list |
| Open file | Click file name -> Opens in system default app | Uses shell.openPath via IPC |
| Rename file | Click rename icon -> Inline rename | Updates Dexie DB |
| Delete file | Click delete icon -> Confirm popup -> Delete | Removes from DB and disk |
| Batch delete | Check files -> Batch delete -> Confirm | Validates no paintings references, bulk delete |
| Select all | Check "Select All" -> All files selected | Indeterminate state supported |
| Filter by type | Click sidebar tab (Document/Image/Text/All) | Dexie where().equals() filter |

### Runtime Behavior
- File metadata stored in Dexie (IndexedDB) with fields: id, name, ext, size, type, count, created_at, path
- Files stored on disk in app data directory (getFilesDir())
- File types: document (.pdf, .docx, etc.), image (.png, .jpg, etc.), text (.txt, .md, etc.)
- useLiveQuery for reactive DB queries
- Paintings reference check before delete (prevents deleting files used in image generation)
- File deduplication by MD5 hash on upload
- formatFileSize utility for human-readable sizes

## 11. Feature Contracts

### IPC Contracts (Main <-> Renderer)

| Channel | Direction | Payload | Response |
|---------|-----------|---------|----------|
| `file:openPath` | renderer->main | `string` (path) | void |
| `file:select` | renderer->main | `OpenDialogOptions` | `FileMetadata[]` |
| `file:get` | renderer->main | `string` (path) | `FileMetadata` |
| `file:delete` | renderer->main | `string` (id) | void |

### Dexie Schema Contract

```typescript
interface FileMetadata {
  id: string
  name: string
  ext: string
  size: number
  type: FileType  // 'document' | 'image' | 'text'
  count: number   // reference count
  created_at: number
  path: string    // relative path within storage dir
}
```

### Store Contract

Files feature primarily uses Dexie (IndexedDB) for data, not Zustand. Local component state manages sort/selection.
