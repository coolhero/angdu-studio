## 9. For /speckit.specify

### Summary
F004-ai-engine provides the provider abstraction layer supporting 20+ AI providers, model selection, streaming/completion, proxy management, memory integration, and copilot OAuth. It is the central service layer connecting settings (F003) to chat (F006).

### Scenarios
1. User selects model -> provider client created with API key
2. Chat sends message -> streaming tokens received
3. Provider with custom proxy -> requests routed through proxy
4. Memory enabled -> context memory added to prompts
5. Copilot OAuth flow -> device code authentication

### Draft Functional Requirements
- **FR-026**: Provider abstraction supporting 20+ AI providers
- **FR-027**: Model selection per assistant/chat (default, quick, translate)
- **FR-028**: Streaming token delivery to chat UI
- **FR-029**: Proxy support (system/custom/none) for all AI requests
- **FR-030**: AI memory integration (add/search/manage memories)
- **FR-031**: GitHub Copilot OAuth integration
- **FR-032**: Provider-specific settings (Ollama keepAlive, VertexAI, AWS Bedrock)

### Draft Scenarios
- **SC-011**: Given provider configured, when message sent, then response streamed token by token
- **SC-012**: Given custom proxy set, when AI request made, then request routes through proxy
- **SC-013**: Given memory enabled, when sending message, then relevant memories included in context

### Edge Cases
- Provider API key invalid -> error propagation to chat
- Network timeout during streaming -> partial response handling
- Provider rate limiting -> retry/backoff
- Proxy authentication failure
- Multiple concurrent requests to same provider
