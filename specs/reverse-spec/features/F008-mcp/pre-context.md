## 1. Runtime Exploration Results

**Screen**: Settings -> MCP Servers

**Layout**: Settings page with MCP Servers section, server list with toggle switches, server configuration forms, built-in server cards

### UI Elements
- Server list: Name, type badge (stdio/inMemory/sse/streamableHttp), active toggle switch, status indicator
- Server actions: Add, Edit, Remove, Restart, Stop, Check Connectivity
- Built-in servers section: 11 pre-configured servers (hub, mcpAutoInstall, memory, sequentialThinking, braveSearch, fetch, filesystem, difyKnowledge, python, didi-mcp, browser, nowledgeMem)
- Server configuration form: Name, command, args, baseUrl, env vars, type selector, headers, registry URL, disabled tools list, trust toggle
- Server logs: Per-server log viewer with timestamp, level, message, source
- Tool permission: Per-tool enable/disable within a server (disabledTools array)
- DXT support: Upload .dxt package to install MCP servers
- Progress events: Tool call progress notifications

### User Flows
| Flow | Steps | Observations |
|------|-------|--------------|
| Add MCP server | Click Add -> Fill config (name, command/URL, type, env) -> Save | Server added to list, not auto-started |
| Activate server | Toggle switch ON -> Server initializes | Connects via transport (stdio/SSE/HTTP/inMemory), ping check |
| List tools | Click server -> View tools tab | Shows tool name, description, input schema |
| Call tool | From chat (function calling) -> Tool invocation | Abort support, progress events, call ID tracking |
| Check connectivity | Click connectivity check button | Pings server, lists tools as health check |
| Restart server | Click restart -> Close + reconnect | Clears cache, re-initializes client |
| Install DXT | Upload .dxt file -> Extract -> Configure | DXT package with manifest for auto-config |
| View resources | Click Resources tab on server | Lists available MCP resources |
| View prompts | Click Prompts tab on server | Lists available MCP prompts |
| View server logs | Click Logs tab on server | Real-time log entries from server |

### Runtime Behavior
- Client-per-server model with caching (Map<serverKey, Client>)
- Pending client initialization prevents duplicate connections
- Transport types: StdioClientTransport, SSEClientTransport, StreamableHTTPClientTransport, InMemoryTransport
- OAuth flow support for SSE/HTTP transports with callback server
- Tool results cached with 5-minute TTL
- Notification handlers for tool/resource/prompt list changes
- Sensitive fields redacted in logs (authorization, apiKey, token)

## 12. For /speckit.specify

- Transport selection logic is complex (stdio vs SSE vs HTTP vs inMemory) -- specify decision tree
- OAuth flow involves callback server with 5-minute timeout -- specify the full auth flow
- Built-in servers have varying configurations (some need env vars, some need args) -- specify each
- Hub server aggregation (serverId__toolName format) is critical for auto mode -- specify naming
- Tool permission (disabledTools) filters at aggregation time -- specify filter behavior
- DXT package support adds install/uninstall flow -- specify lifecycle
- Server log buffer (200 entries) truncates old entries -- specify retention policy

## 13. For /speckit.plan

- Start with basic server CRUD (add/remove/toggle) before transport complexity
- Implement stdio transport first (most common), then inMemory for builtins, then SSE/HTTP
- Built-in servers can be added incrementally (start with fetch, memory, sequentialThinking)
- Tool calling integrates with F005-chat -- plan that integration point
- Hub server can be deferred until auto-mode is needed
- OAuth flow can be deferred (only needed for SSE/HTTP servers that require auth)
- DXT support can be a later phase

## 14. For /speckit.analyze

- Server key is JSON.stringify of connection config -- changes to any field create new connection
- Pending client dedup prevents race conditions during concurrent activation requests
- Command resolution tries system path first, falls back to bundled bun
- Bun proxy not supported (https://github.com/oven-sh/bun/issues/16812) -- removeEnvProxy when using bun
- Cache TTL of 5 minutes balances freshness with server load
- Notification handlers clear specific caches when server-side data changes
- ServerLogBuffer limits memory usage (200 entries per server)
- nowledgeMem uses HTTP transport despite being marked as inMemory (special case)
