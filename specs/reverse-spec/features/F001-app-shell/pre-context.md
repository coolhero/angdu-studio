## 9. For /speckit.specify

### Summary
F001-app-shell provides the Electron main process infrastructure: window management (main + mini), system tray, auto-update, global shortcuts, IPC bridge, theme synchronization, and platform-specific behaviors.

### Scenarios
1. App cold start -> main window creation with state restoration
2. App cold start with `launchToTray` -> hidden start, tray only
3. Single instance enforcement -> second instance focuses existing window
4. Window close -> tray minimize (if configured) or quit
5. Mini window toggle via global shortcut
6. Auto-update check on startup
7. Theme toggle propagation to all windows
8. Protocol URL handling (`cherrystudio://data?...`)

### Draft Functional Requirements
- **FR-001**: Single instance enforcement with second-instance window focus
- **FR-002**: Main window creation with frameless mode (macOS traffic lights, Win/Linux custom controls)
- **FR-003**: Window state persistence (position, size, maximized)
- **FR-004**: Mini window (quick assistant) with always-on-top, pin support
- **FR-005**: System tray with configurable show/hide, context menu
- **FR-006**: Auto-update with channel management (latest/rc/beta) and mirror selection
- **FR-007**: Global shortcuts (show app, mini window, zoom, selection assistant)
- **FR-008**: Theme synchronization (dark/light/system) across all windows
- **FR-009**: IPC bridge via preload with contextIsolation
- **FR-010**: Protocol handler for deep linking

### Draft Scenarios
- **SC-001**: Given app is running, when user launches again, then existing window focuses
- **SC-002**: Given trayOnClose=true, when user closes window, then window hides to tray
- **SC-003**: Given quickAssistant enabled, when global shortcut pressed, then mini window toggles
- **SC-004**: Given auto-update enabled, when update available, then download starts and notification sent

### Edge Cases
- Renderer crash recovery (reload if not rapid-fire crashes)
- Mini window multi-monitor positioning (move to cursor's screen)
- Linux Wayland vs X11 differences (GlobalShortcutsPortal, setVisibleOnAllWorkspaces)
- macOS fullscreen state management on close/reopen

## 11. Feature Contracts

### Guarantees
- **G-001**: Only one app instance runs at a time
- **G-002**: Window state (position, size) persists across restarts
- **G-003**: Theme changes propagate to all open windows immediately
- **G-004**: Global shortcuts work when app is in background (show_app, mini_window)
- **G-005**: Preload API is the only bridge between main and renderer

### Dependencies on Other Features
None

### Failure Modes
- **FM-001**: Renderer crash -> auto-reload (throttled to prevent crash loop, exits if <1min between crashes)
- **FM-002**: Update check failure -> returns current version with null updateInfo
- **FM-003**: Shortcut registration failure -> logged and skipped (non-fatal)
- **FM-004**: Tray creation failure -> app continues without tray
