## 1. Runtime Exploration Results

**Screen**: `#/knowledge`

**Layout**: Navbar ("Knowledge Base" title) + left sidebar (knowledge base list, draggable, with + Add button) + main content area (tabbed: Files, Notes, Directories, URLs, Sitemaps; Videos tab hidden)

### UI Elements
- Left sidebar: Draggable list of knowledge bases with Book icon, context menu (Rename, Settings, Delete with confirm dialog)
- Header bar: Settings button (gear icon), embedding model tag with provider tooltip, rerank model tag (if configured), Search icon
- Tab bar: Files | Notes | Directories | URLs | Sitemaps (each with item count badge in green/grey)
- Per-tab content: Item lists with processing status indicators (spinner, check, error), progress bars, refresh/retry buttons
- Add Knowledge Base popup: Name, embedding model selection, chunk size, chunk overlap, document count, preprocessing provider, rerank model
- Edit Knowledge Base popup: Same fields as Add, with model change support
- Knowledge Search popup: Search input, results with similarity scores

### User Flows
| Flow | Steps | Observations |
|------|-------|--------------|
| Create knowledge base | Click + Add -> Fill name, select embedding model -> Create | RAG application created via EmbedJS |
| Add file to KB | Select Files tab -> Upload file -> Processing starts | Shows processing status, progress for PDFs |
| Add URL to KB | Select URLs tab -> Enter URL -> Process | WebLoader extracts content |
| Add directory | Select Directories tab -> Select folder -> All files processed | Shows directory processing percent |
| Add note to KB | Select Notes tab -> Add note content | NoteLoader for text content |
| Add sitemap | Select Sitemaps tab -> Enter sitemap URL | SitemapLoader processes all pages |
| Search KB | Click search icon -> Enter query -> View results | Vector similarity search with optional reranking |
| Delete KB | Right-click -> Delete -> Confirm | Cleans up RAG app, DB files, pending delete on restart |
| Rename KB | Right-click -> Rename -> Enter name | Updates base name and timestamp |
| Reorder KBs | Drag and drop in sidebar | DraggableList component |

### Runtime Behavior
- Processing uses workload-based queue (80MB max, 30 items max concurrent)
- PDF preprocessing via Minerou, Doc2x, Mistral, PaddleOCR providers
- Progress events: `file-preprocess-finished`, `file-preprocess-progress`, `file-ocr-progress`, `directory-processing-percent`
- Startup cleanup deletes pending knowledge bases from previous failed sessions
- LibSqlDb vector database per knowledge base

## 12. For /speckit.specify

- Knowledge base CRUD is straightforward but the processing queue system is complex -- specify workload limits and concurrent processing behavior
- Preprocessing pipeline has 5 providers (Default, Minerou, Doc2x, Mistral, PaddleOCR) -- each needs its own error handling spec
- Search + Rerank is a two-step pipeline -- specify fallback when rerank model not configured
- Item types (file, directory, url, sitemap, note, video) each have different loader behavior -- specify deduplication rules per type
- Startup cleanup (pending delete) is a resilience pattern -- specify the recovery flow

---

## 13. For /speckit.plan

- KB creation is independent of other features except F003 (embedding model) and F010 (file paths)
- Start with core CRUD (create/delete/rename) before adding item processing
- Processing queue can be simplified initially (no workload limits) then optimized
- Preprocessing providers can be added incrementally (start with DefaultPreprocessProvider)
- Search and rerank can be separate implementation phases

---

## 14. For /speckit.analyze

- The workload queue system (80MB max, 30 items max) prevents memory exhaustion -- maintain these limits
- LibSqlDb paths use sanitizeFilename to handle special characters in IDs
- Pending delete pattern handles DB file lock issues on Windows
- Directory processing sends progress events per-file, not per-chunk
- PreprocessProvider checks for cached results before re-processing
- Knowledge bases store items inline (not normalized) -- consider if this scales for large bases
