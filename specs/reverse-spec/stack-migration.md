# Stack Migration Plan — Angdu Studio

> Generated by `/reverse-spec` Phase 4 — 2026-03-14
> Source: Cherry Studio v1.7.24
> Strategy: New Stack (selective migration — only UI and State layers change)

---

## 1. Migration Overview

| Category | Cherry Studio (Source) | Angdu Studio (Target) | Migration Type |
|----------|----------------------|----------------------|----------------|
| Framework | Electron + React + TypeScript | Electron 40 + React 19 + TypeScript | **Same** (version bump) |
| Build Tool | electron-vite | electron-vite | **Same** |
| **UI Library** | **Ant Design 5 + styled-components** | **shadcn/ui + Tailwind CSS** | **REWRITE** |
| **State Management** | **Redux Toolkit + redux-persist** | **Zustand + electron-store** | **REWRITE** |
| AI SDK | Vercel AI SDK (`ai` package) | Vercel AI SDK (`ai` package) | **Same** |
| IPC Layer | Typed enum channels (`IpcChannel`) | Typed enum channels (`IpcChannel`) | **Same** |
| Database | Dexie.js (IndexedDB) | Dexie.js (IndexedDB) | **Same** |
| i18n | i18next + react-i18next | i18next + react-i18next | **Same** |
| Testing | Vitest + Playwright | Vitest + Playwright | **Same** |
| Linting | Biome + ESLint | Biome + ESLint | **Same** |
| Package Manager | pnpm (workspace) | pnpm (workspace) | **Same** |

**Key insight**: Only 2 of 11 technology categories actually change. The migration is focused and bounded.

#### Styling Approach Change

| Aspect | Cherry Studio (styled-components) | Angdu Studio (Tailwind CSS) |
|--------|----------------------------------|----------------------------|
| Styling method | CSS-in-JS, template literals | Utility classes in JSX |
| Theme variables | `${props => props.theme.xxx}` | CSS custom properties + Tailwind theme |
| Dynamic styles | JS expressions in template | `cn()` utility + conditional classes |
| Component variants | Props → styled interpolation | CVA (class-variance-authority) |
| Global styles | `createGlobalStyle` | `globals.css` + Tailwind `@layer` |
| Dark mode | Theme provider + JS variables | `dark:` prefix classes + CSS variables |
| Responsive | Media queries in JS | `sm:` / `md:` / `lg:` breakpoint prefixes |

**Migration Pattern**:
```
// Cherry Studio (styled-components)
const StyledButton = styled.button<{ $primary?: boolean }>`
  background: ${p => p.$primary ? 'var(--color-primary)' : 'transparent'};
  padding: 8px 16px;
  border-radius: 6px;
`

// Angdu Studio (Tailwind + shadcn)
<Button variant={primary ? "default" : "ghost"} className="px-4 py-2 rounded-md">
```

#### Key Differences to Watch

1. **Layout system**: Ant Design's `Row`/`Col` grid → Tailwind `grid` / `flex` utilities
2. **Form handling**: Ant `Form` has built-in validation → use React Hook Form + Zod
3. **Notification system**: Ant `message` / `notification` → Sonner toast
4. **Icon library**: `@ant-design/icons` → `lucide-react` (shadcn default)
5. **Color system**: Ant Design token system → Tailwind CSS custom properties in `globals.css`

#### Persistence Approach Change

| Aspect | Cherry Studio (redux-persist) | Angdu Studio (electron-store) |
|--------|------------------------------|-------------------------------|
| Storage backend | Renderer localStorage | Main process JSON file |
| Persist trigger | Redux middleware (every action) | Zustand `subscribe` + debounce |
| Rehydration | `REHYDRATE` action on app start | `electron-store.get()` via IPC on init |
| Versioning | `version: 199` + migrate function | electron-store migrations |
| Blacklist | Array of slice names | Simply don't persist those stores |
| Cross-window sync | `StoreSyncService` middleware | IPC broadcast on state change |
| Data location | Browser storage (ephemeral) | App data directory (durable) |

#### Migration Pattern

```typescript
// Cherry Studio (Redux Toolkit)
const assistantsSlice = createSlice({
  name: 'assistants',
  initialState: { list: [], active: null },
  reducers: {
    addAssistant: (state, action) => { state.list.push(action.payload) },
    setActive: (state, action) => { state.active = action.payload },
  },
})
export const { addAssistant, setActive } = assistantsSlice.actions
export default assistantsSlice.reducer

// Usage:
dispatch(addAssistant(newAssistant))
const list = useAppSelector(s => s.assistants.list)

// Angdu Studio (Zustand)
export const useAssistantStore = create<AssistantStore>()(
  persist(
    (set, get) => ({
      list: [],
      active: null,
      addAssistant: (assistant) => set(s => ({ list: [...s.list, assistant] })),
      setActive: (id) => set({ active: id }),
    }),
    { name: 'assistants', storage: electronStoreStorage }
  )
)

// Usage:
useAssistantStore.getState().addAssistant(newAssistant)
const list = useAssistantStore(s => s.list)
```

#### Middleware Migration

| Redux Middleware | Zustand Equivalent |
|-----------------|-------------------|
| `redux-persist` | Zustand `persist` middleware with custom `electron-store` storage adapter |
| `StoreSyncService.createMiddleware()` | Custom `subscribe` handler that broadcasts via IPC |
| Serializable check | Not needed (Zustand is plain JS) |
| Redux DevTools | Zustand `devtools` middleware |

## 5. Risks and Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| **Ant Design implicit behaviors** — Some Ant components handle edge cases (form validation, focus management) that shadcn does not | Medium | High | Document each Ant component's implicit behavior before replacing. Test edge cases explicitly. |
| **Styled-components theme references scattered** — CS uses `var(--color-xxx)` CSS variables extensively; some may be Ant Design theme tokens | Low | Medium | Audit all CSS variables. Map Ant Design tokens to Tailwind CSS custom properties in `globals.css`. |
| **Redux persist migration data** — Users migrating from Cherry Studio would need data migration | Low | Low | Not applicable — Angdu Studio is a fresh product, no data migration from Cherry Studio needed. |
| **Zustand devtools maturity** — Redux DevTools are more mature than Zustand devtools middleware | Low | Low | Zustand devtools middleware is sufficient. Add custom logging in development mode. |
| **Cross-window state sync complexity** — Redux StoreSyncService is battle-tested; Zustand equivalent is custom | Medium | Medium | Build IPC-based sync early. Test with multi-window scenarios (main window + mini window + selection window). |
| **Form complexity** — Ant Design Form has rich validation; React Hook Form + Zod is different paradigm | Medium | Medium | Use Zod schemas matching store types. Test all validation paths. |
| **Bundle size** — Tailwind + shadcn should be smaller than Ant Design, but verify | Low | Low | Monitor bundle size from first feature. Set size budget. |
| **Tailwind class verbosity** — Long class strings can reduce readability | Low | High | Use `cn()` utility aggressively. Extract repeated patterns to component variants via CVA. |
