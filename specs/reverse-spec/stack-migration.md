> Generated by `/reverse-spec` Phase 4 — 2026-03-13
> Source stack → Target stack migration analysis

## 1. Migration Overview

| # | Category | Source (Cherry Studio) | Target (Angdu Studio) | Impact |
|---|----------|----------------------|----------------------|--------|
| M1 | Component Library | Ant Design 5 + @ant-design/icons + @ant-design/cssinjs | shadcn/ui + Radix UI + Lucide React | **High** — every UI component changes |
| M2 | State Management | Redux Toolkit + react-redux + redux-persist | Zustand 5 + persist middleware | **High** — all store slices rewritten |
| M3 | CSS Approach | styled-components + Ant Design CSS-in-JS + CSS vars | Tailwind CSS 4 only (utility-first) | **High** — all component styling changes |
| M4 | Persistence | redux-persist (localStorage) | Zustand persist middleware (localStorage) | **Medium** — same storage, different API |

## 2. M1: Ant Design 5 → shadcn/ui + Radix UI

### Rationale

- Ant Design is opinionated with heavy CSS-in-JS runtime; shadcn/ui provides unstyled, composable primitives
- shadcn/ui components are copy-pasted into the project (not a dependency), enabling full control
- Radix UI provides accessible, unstyled primitives that align with Tailwind styling
- Lucide React replaces @ant-design/icons with tree-shakeable SVG icons

### Key Differences

| Aspect | Ant Design 5 | shadcn/ui + Radix |
|--------|-------------|-------------------|
| Philosophy | Full-featured, opinionated | Unstyled primitives, copy-paste |
| Styling | CSS-in-JS (@ant-design/cssinjs) | Tailwind CSS classes |
| Theming | ConfigProvider + token system | CSS variables + Tailwind theme |
| Icons | @ant-design/icons (heavy bundle) | Lucide React (tree-shakeable) |
| Form | Form + Form.Item + rules | react-hook-form + zod (recommended) |
| Table | Table with built-in sort/filter/pagination | @tanstack/react-table (headless) |
| Modal/Dialog | Modal component | Dialog from Radix (via shadcn/ui) |
| Notification | message.success/error/warning | Sonner toast (via shadcn/ui) |
| Select/Dropdown | Select, Dropdown components | Select, DropdownMenu from Radix |
| Layout | Layout, Sider, Header | div + Tailwind flex/grid |
| Tabs | Tabs, TabPane | Tabs from Radix (via shadcn/ui) |

### Impact by Feature

- **F001 app-shell**: Custom titlebar uses minimal Ant Design; mostly CSS migration
- **F002 navigation**: Sidebar icons switch from antd icons to Lucide; Layout → flex
- **F003 settings**: Heavy Ant Design usage (Form, Input, Select, Switch, Slider, Collapse, Tabs) — highest migration effort
- **F004 ai-engine**: Minimal UI; mostly internal logic
- **F005 assistant**: Modal, List, Card, Avatar components
- **F006 chat**: Message bubbles (custom styled), Input/Textarea, Dropdown, Popover, Tooltip — medium effort
- **F007 file-management**: Table/List, Upload, Button
- **F008 mcp**: Settings forms, List
- **F009 knowledge-base**: Table, Upload, Progress, Modal
- **F010 notes**: TipTap editor (unchanged), tree view → custom or Radix Accordion
- **F011 data-sync**: Forms, Progress, Button
- **F012 creative-tools**: Various pages; each has moderate Ant Design usage

|-----------|----------------------|-------|

## 3. M2: Redux Toolkit → Zustand 5

### Rationale

- Zustand has dramatically less boilerplate than Redux Toolkit
- No need for Provider wrapper, action creators, or middleware setup
- Zustand persist middleware replaces redux-persist with simpler API
- Better TypeScript inference without extra type annotations
- Zustand stores are independent; no single root reducer

### Key Differences

| Aspect | Redux Toolkit | Zustand 5 |
|--------|-------------|-----------|
| Store creation | configureStore + combineReducers | create() per store |
| Slice definition | createSlice({ reducers, extraReducers }) | (set, get) => ({...}) |
| Dispatch | useAppDispatch() + dispatch(action()) | direct: useStore.getState().action() |
| Selectors | useAppSelector(s => s.slice.field) | useStore(s => s.field) |
| Async | createAsyncThunk | plain async functions in store |
| Persistence | redux-persist + persistReducer | persist() middleware |
| DevTools | Redux DevTools (built-in) | devtools() middleware |
| Multi-window sync | Custom StoreSyncService middleware | Custom middleware (similar pattern) |
| Provider | `<Provider store={store}>` | None needed |

### Cherry Studio Redux Store Slices → Zustand Stores

| assistants | useAssistantStore | Yes | F005 |

### Migration Pattern

```
// Redux Toolkit (source)
const assistantsSlice = createSlice({
  name: 'assistants',
  initialState: { list: [], defaultAssistant: null },
  reducers: {
    addAssistant: (state, action) => { state.list.push(action.payload) },
    removeAssistant: (state, action) => { ... }
  }
})

// Zustand 5 (target)
export const useAssistantStore = create<AssistantState>()(
  persist(
    (set, get) => ({
      list: [],
      defaultAssistant: null,
      addAssistant: (assistant) => set(s => ({ list: [...s.list, assistant] })),
      removeAssistant: (id) => set(s => ({ list: s.list.filter(a => a.id !== id) })),
    }),
    { name: 'angdu-assistants' }
  )
)
```

## 4. M3: styled-components → Tailwind CSS 4

### Rationale

- Eliminates CSS-in-JS runtime overhead
- Tailwind CSS 4 uses native CSS cascade layers and `@theme` directives (no PostCSS)
- Consistent utility-first approach across all components
- Better alignment with shadcn/ui (designed for Tailwind)
- `tailwind-merge` + `clsx` for conditional class composition

### Key Differences

| Aspect | styled-components | Tailwind CSS 4 |
|--------|-------------------|----------------|
| Approach | CSS-in-JS, component-scoped | Utility-first, class-based |
| Runtime | JS runtime generates CSS | Zero JS runtime (build-time) |
| Theming | ThemeProvider + props | CSS variables + @theme |
| Dynamic styles | Template literals + props | Conditional classes (clsx/cn) |
| Variants | Props-based logic | class-variance-authority (cva) |
| Global styles | createGlobalStyle | @layer base in CSS |
| Media queries | Template literals | Responsive prefixes (sm:, md:, lg:) |

### Migration Pattern

```
// styled-components (source)
const ChatContainer = styled.div`
  display: flex;
  flex-direction: column;
  height: 100%;
  background: ${props => props.theme.chatBg};
  padding: ${props => props.$compact ? '8px' : '16px'};
`

// Tailwind CSS 4 (target)
function ChatContainer({ compact, children }) {
  return (
    <div className={cn(
      "flex flex-col h-full bg-chat",
      compact ? "p-2" : "p-4"
    )}>
      {children}
    </div>
  )
}
```

### CSS Variable Mapping

Cherry Studio uses CSS custom properties extensively. These transfer directly to Tailwind's `@theme`:

```css
/* Cherry Studio vars → Tailwind @theme */
@theme {
  --color-sidebar-bg: var(--sidebar-bg);
  --color-chat-bg: var(--chat-bg);
  --sidebar-width: 50px;
  --navbar-height: 40px;
}
```

## 5. M4: redux-persist → Zustand Persist Middleware

### Rationale

- Zustand's built-in persist middleware is simpler and type-safe
- Same underlying storage (localStorage)
- Migration versioning via `version` + `migrate` function

### Key Differences

| Aspect | redux-persist | Zustand persist |
|--------|-------------|-----------------|
| Setup | persistReducer() wrapping | persist() middleware wrapping |
| Storage key | Single key ('cherry-studio') | Per-store key ('angdu-assistants', etc.) |
| Blacklist/Whitelist | blacklist/whitelist arrays | partialize() function |
| Version migration | version + migrate function | version + migrate function (similar) |
| Rehydration | REHYDRATE action + PersistGate | onRehydrateStorage callback |
| Flush | persistor.flush() | useStore.persist.rehydrate() |

### Storage Key Migration

Cherry Studio stores everything under one key `cherry-studio`. Angdu Studio splits into per-feature stores:

| redux-persist key | Zustand store keys |
|------------------|--------------------|
| `cherry-studio` (single) | `angdu-assistants`, `angdu-settings`, `angdu-llm`, `angdu-mcp`, `angdu-knowledge`, etc. |

These patterns are stack-independent and carry over without rethinking:

| Pattern | Description | Features |
|---------|-------------|----------|
| IPC bridge (main↔renderer) | ipcMain.handle / ipcRenderer.invoke pattern | All |

| MCP server lifecycle | Spawn/connect/disconnect MCP servers | F008 |

## 7. Patterns Requiring Rethinking

| Pattern | Why It Changes | New Approach |
|---------|---------------|-------------|
| Ant Design ConfigProvider theming | Ant Design token system is proprietary | CSS variables + Tailwind @theme + shadcn/ui theming |
| Ant Design Form validation | Form.Item + rules pattern | react-hook-form + zod schemas |
| Ant Design Table with server-side features | Built-in sort/filter/pagination | @tanstack/react-table (headless) + shadcn DataTable |
| Redux dispatch pattern | dispatch(actionCreator(payload)) | Direct store method calls: useStore.getState().action(payload) |
| Redux selectors with reselect | createSelector for memoized derivation | Zustand selectors with shallow equality |
| Redux thunks | createAsyncThunk for async flows | Async methods directly in Zustand store |
| styled-components dynamic props | `${props => props.theme.color}` | cn() with Tailwind conditional classes |
| styled-components media queries | Template literal breakpoints | Tailwind responsive prefixes (sm:, md:, lg:) |
| Ant Design message/notification | Imperative toast API | Sonner toast via shadcn/ui |
| Redux multi-window sync | Custom middleware + IPC broadcast | Zustand middleware + IPC broadcast (same concept, new API) |
| redux-persist migration | Single root migrate function (version 199) | Per-store migrate functions |
| Ant Design Layout (Sider, Content) | Component-based layout | Tailwind flex/grid layout |

## 8. Risks and Mitigations

| # | Risk | Impact | Mitigation |
|---|------|--------|-----------|
| R1 | Ant Design component coverage gap — shadcn/ui may lack equivalent for niche antd components | Blocked feature implementation | Audit all Ant Design components used per feature; build custom components where shadcn/ui lacks coverage |
| R2 | Redux → Zustand migration breaks multi-window state sync | Main + mini windows desync | Reimplement StoreSyncService as Zustand middleware; test multi-window scenarios early (RG-1) |
| R3 | redux-persist data migration — existing users with Cherry Studio data | Data loss on upgrade | Not applicable for Angdu Studio (clean rebuild, no migration from Cherry Studio user data) |
| R4 | styled-components to Tailwind — inconsistent visual output | UI regressions | Use visual regression tests; reference Cherry Studio screenshots during development |
| R5 | Tailwind CSS 4 alpha/beta features | Build instability | Pin Tailwind version; monitor release notes |
| R6 | Large store migration (26 Redux slices) | Missed state fields or broken selectors | Generate Zustand stores mechanically from Redux slice interfaces; verify with TypeScript |
| R7 | Ant Design patches (`antd@5.27.0` patch) | Patch logic needs re-evaluation | Review patch purpose; determine if shadcn/ui equivalent needs similar fix |
| R8 | CSS-in-JS removal breaks Ant Design internal styles | Component rendering issues during migration | Remove Ant Design entirely per feature (no partial migration) |

## 9. Per-Feature Migration Notes

### F001 app-shell
- **UI**: Minimal Ant Design (mostly native Electron APIs). Custom titlebar CSS moves from styled-components to Tailwind.
- **State**: `runtime` slice (non-persisted) → `useRuntimeStore`. `selectionStore` → `useSelectionStore`.
- **Priority**: Low migration effort.

### F002 navigation
- **UI**: Sidebar uses antd icons → Lucide React. Layout component → Tailwind flex. Theme toggle → shadcn Switch/Button.
- **State**: No dedicated slice; reads from `settings`.
- **Priority**: Medium effort — sidebar is core UI.

### F003 settings
- **UI**: Heaviest Ant Design usage (Form, Input, Select, Switch, Slider, Collapse, Tabs, List, Typography). Every settings page needs rewrite.
- **State**: `settings`, `shortcuts`, `ocr` slices → separate Zustand stores.
- **Priority**: **Highest migration effort** of any feature.

### F004 ai-engine
- **UI**: Model selector dropdown (antd Select → shadcn Select). Provider settings handled by F003.
- **State**: `llm`, `memory`, `copilot`, `websearch`, `preprocess` slices → Zustand stores.
- **Business logic**: Provider abstraction, AI SDK integration — transfers directly.
- **Priority**: Medium effort — many store slices but minimal UI.

### F005 assistant
- **UI**: Assistant list, CRUD modals, preset cards (antd Modal, List, Card, Avatar → shadcn equivalents).
- **State**: `assistants` slice → `useAssistantStore`.
- **Priority**: Medium effort.

### F006 chat
- **UI**: Message bubbles (mostly custom styled-components → Tailwind), input toolbar, message context menus. Topic tabs (antd Tabs-like → shadcn Tabs or custom).
- **State**: `messages`, `messageBlocks`, `tabs`, `inputTools` slices (non-persisted) → Zustand stores.
- **Priority**: High effort — most complex UI surface.

### F007 file-management
- **UI**: File list/table, upload area (antd Upload/Table → shadcn DataTable + custom upload).
- **State**: No dedicated Redux slice; uses IPC to main process FileStorage.
- **Priority**: Low-medium effort.

### F008 mcp
- **UI**: MCP settings page (Form fields), MCP popup in chat toolbar (custom).
- **State**: `mcp`, `toolPermissions` slices → Zustand stores.
- **Priority**: Medium effort.

### F009 knowledge-base
- **UI**: KB list, document ingestion progress (antd Table, Progress, Modal → shadcn equivalents).
- **State**: `knowledge` slice → `useKnowledgeStore`.
- **Business logic**: Embedding pipeline (LangChain) — transfers directly.
- **Priority**: Medium effort.

### F010 notes
- **UI**: TipTap editor (unchanged), note tree (possibly antd Tree → custom tree with Radix Accordion).
- **State**: `note` slice → `useNoteStore`.
- **Priority**: Low effort — TipTap is the main UI, and it doesn't change.

### F011 data-sync
- **UI**: Backup/restore UI (forms, progress bars). Sync settings (antd Form → shadcn).
- **State**: `backup`, `nutstore` slices → Zustand stores.
- **Business logic**: WebDAV, S3, Nutstore clients — transfer directly.
- **Priority**: Low-medium effort.

### F012 creative-tools
- **UI**: Multiple sub-pages (paintings, translate, code, mini-apps, OpenClaw, launchpad). Each has moderate antd usage.
- **State**: `paintings`, `translate`, `codeTools`, `minapps`, `openclaw` slices → Zustand stores.
- **Priority**: Medium-high effort (breadth of pages, but each is relatively simple).
