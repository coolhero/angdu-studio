# Implementation Plan: Core Platform

**Branch**: `001-core-platform` | **Date**: 2026-03-04 | **Spec**: `specs/001-core-platform/spec.md`
**Input**: Feature specification from `/specs/001-core-platform/spec.md`

## Summary

Build the foundational Electron shell for Cherry Studio: 3-process architecture (main/preload/renderer) with typed IPC bridge, window management (main + mini window), configuration persistence via electron-store, i18n with 11 locales, CSS-variable theming with Tailwind CSS 4, file storage with Dexie IndexedDB, centralized Winston logging, system tray, platform detection, global keyboard shortcuts, deep link protocol handling, and renderer crash recovery.

Technical approach: Side-effect-ordered imports for bootstrap sequencing (R1), single flat IpcChannel enum in shared package (R2), generic get/set ConfigManager with EventEmitter pub/sub (R3), fresh Dexie v1 schema with only F001 tables (R4), electron-vite 3-section config (R5), nested-domain preload API surface (R6), Zustand stores with persist + BroadcastChannel sync (R7), TanStack Router with file-based routes (R8), CSS variables + Tailwind dark mode (R9).

## Technical Context

**Language/Version**: TypeScript 5.8, Node.js (Electron 40 / Chromium)
**Primary Dependencies**: Electron 40, React 19, electron-vite 5, Zustand, TanStack Router, shadcn/ui + Radix UI, Tailwind CSS 4, i18next + react-i18next, dayjs, electron-store, Dexie 4, Winston, chokidar, Zod
**Storage**: Dexie 4 (IndexedDB) for client-side data, electron-store for configuration persistence, local filesystem for file storage
**Testing**: Vitest for unit/integration, Playwright for E2E
**Target Platform**: Cross-platform desktop: macOS, Windows, Linux (Wayland, AppImage, portable)
**Project Type**: Desktop application (Electron)
**Performance Goals**: <3s app launch, <200ms theme switch, <100ms non-IO IPC round-trip
**Constraints**: All data local (no mandatory cloud), context isolation enforced, forward-only DB migrations
**Scale/Scope**: ~126 IPC channels across 12 domains, 22 functional requirements, 11 locales

**Structure Decision**: Electron multi-process layout with `src/main/`, `src/preload/`, `src/renderer/` mirroring Electron's process model. Shared types in `packages/shared/` for cross-process type safety. IPC handlers separated by domain in `src/main/ipc/`. Services encapsulate main-process logic. Preload API uses nested domain objects. Renderer follows React conventions with stores, hooks, routes, and i18n.
