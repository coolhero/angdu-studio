# Implementation Plan: Core Platform

**Branch**: `001-core-platform` | **Date**: 2026-03-04 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-core-platform/spec.md`

## Summary

Build the foundational Electron shell for Cherry Studio — a cross-platform desktop AI assistant. This feature establishes the 3-process architecture (main/preload/renderer), typed IPC bridge, window management (main + mini), configuration persistence, theme system, file storage, i18n (10 locales), logging, Dexie IndexedDB, system tray, global shortcuts, and deep link protocol. All downstream features (F002-F005) depend on this foundation.

## Technical Context

**Language/Version**: TypeScript 5.8
**Primary Dependencies**: Electron 40, React 19, electron-vite 5, Zustand, TanStack Router, shadcn/ui + Radix UI, Tailwind CSS 4, i18next/react-i18next, Dexie 4, Winston, electron-store, chokidar
**Storage**: Dexie IndexedDB (renderer), electron-store (main), local filesystem
**Testing**: Vitest (unit), Playwright (e2e)
**Target Platform**: macOS, Windows, Linux (cross-platform desktop)
**Project Type**: desktop-app (Electron)
**Performance Goals**: <3s launch, <100ms IPC, <200ms theme switch
**Constraints**: All data local (no cloud), context isolation enforced, single-instance lock
**Scale/Scope**: ~126 IPC channels, 22 functional requirements, 11 user stories

## Architecture Overview

### Process Architecture

```
┌─────────────────┐     ┌──────────────┐     ┌──────────────────────┐
│   Main Process   │◄───►│   Preload     │◄───►│   Renderer Process    │
│   (Node.js)      │ IPC │   Bridge      │     │   (Chromium)          │
│                  │     │              │     │                      │
│  Services:       │     │  window.api  │     │  React 19            │
│  - Window        │     │  { app,      │     │  TanStack Router     │
│  - Config        │     │    file,     │     │  Zustand stores      │
│  - Theme         │     │    config,   │     │  shadcn/ui + Radix   │
│  - FileStorage   │     │    window,   │     │  Tailwind CSS 4      │
│  - Logger        │     │    system,   │     │  Dexie IndexedDB     │
│  - Tray          │     │    ... }     │     │  i18next             │
│  - Shortcuts     │     │              │     │                      │
│  electron-store  │     │  IpcChannel  │     │  BroadcastChannel    │
│  Winston logs    │     │  enum refs   │     │  sync middleware     │
└─────────────────┘     └──────────────┘     └──────────────────────┘
```

### Service Layer Pattern

```
Renderer:  Component → Hook → (Zustand Store | window.api.*)
                                     │                │
                                     ▼                ▼
                              BroadcastChannel    IPC Bridge
                              (cross-window)      (to main)
                                                     │
Main:                                    IPC Handler → Service → Store/FS
```

### Implementation Phases

**Phase 1 — Foundation (US1: App Launch)**
- Electron entry point, bootstrap, single-instance lock
- packages/shared types + IpcChannel enum (initial channels)
- Preload bridge skeleton
- electron-vite build configuration
- Basic main window creation with state persistence
- Platform detection utilities

**Phase 2 — Core Services (US2-US3: Config + Theme)**
- ConfigManager with electron-store and observer pattern
- ThemeService with nativeTheme sync
- Zustand stores (app, theme) with persist middleware
- BroadcastChannel sync middleware
- TanStack Router setup with root layout
- Tailwind CSS 4 + theme CSS variables
- shadcn/ui base component setup

**Phase 3 — File & Database (US4: File Storage)**
- FileStorageService (all CRUD operations, image handling)
- FileWatcherService (chokidar integration)
- Dexie database initialization (version 1: files + settings tables)
- File domain IPC handlers
- FileMetadata entity

**Phase 4 — i18n & Platform (US5, US9: Language + Platform)**
- i18next setup with 10 locales
- dayjs locale integration
- Main process i18n (tray, menu labels)
- Platform-specific window adaptations (macOS title bar, Linux system title bar)
- Portable mode path resolution

**Phase 5 — Desktop Integration (US6-US8: Tray + Mini Window + Shortcuts)**
- TrayService (conditional, platform-specific icons, context menu)
- AppMenuService (macOS only)
- Mini window (WindowService extension — frameless, always-on-top, pin, multi-monitor)
- ShortcutService (global shortcuts)
- ProtocolService (deep link handler)

**Phase 6 — Logging & Polish (US10-US11: Logging + Deep Link)**
- LoggerService (Winston, daily rotation, context-scoped)
- Renderer→main log forwarding
- Renderer crash recovery
- Hardware acceleration toggle
- Proxy configuration
- AES/Zip utility handlers
